# Architecture decision records

Short records of the main design choices in Local Goods: what we decided, why,
and what follows from it. Each one is written so a reviewer can understand the
trade-off in under a minute.

| # | Decision | Status |
|---|---|---|

| [0002](0002-one-bid-and-one-employer-for-the-mvp.md) | One BID and one employer for the MVP | Accepted |
| [0003](0003-fail-closed-fraud-detection.md) | Fail-closed fraud detection | Accepted, implemented |
| [0004](0004-elastic-beanstalk-instead-of-amplify.md) | Elastic Beanstalk instead of Amplify | Accepted, implemented |
| [0005](0005-sqlite-now-rds-for-production-next.md) | SQLite now, Amazon RDS for production next | Superseded by 0006 |
| [0006](0006-amazon-rds-mysql-in-production.md) | Amazon RDS MySQL in production, SQLite for development and tests | Accepted, implemented |
| [0007](0007-fortify-for-login-and-a-role-column.md) | Laravel Fortify for login, and one role column instead of a permissions package | Accepted, implemented |
| [0008](0008-read-only-reviewers-with-single-use-invite-links.md) | Read-only reviewers with single-use invite links | Partly superseded by 0010 |
| [0009](0009-https-through-cloudfront.md) | HTTPS through CloudFront in front of Beanstalk | Accepted, implemented |
| [0010](0010-magic-links-for-reviewers.md) | Magic links for reviewers, and one public judge account | Accepted, implemented |
| [0011](0011-blind-adjudication-of-eval-disagreements.md) | Blind adjudication of eval disagreements by BID staff and contest judges | Retired by 0041; batches in 0020 |
| [0012](0012-one-ledger-three-account-kinds.md) | One ledger with three kinds of account: employee, employer, merchant | Accepted, implemented; platform account added in 0021 |
| [0013](0013-merchant-eligibility-matching.md) | Merchant Eligibility Matching: an AI suggestion, a person's decision, measured against locked labels | Accepted, implemented |
| [0014](0014-employer-program-pending-purchases-and-initials.md) | Employer program, purchases locked until paid, and initials only outside an employee's own wallet | Accepted, implemented |
| [0015](0015-stripe-connect-test-mode-separate-charges-and-transfers.md) | Stripe Connect in test mode: separate charges and transfers, Stripe-funded payouts only | Accepted, implemented |
| [0016](0016-fraud-detection-gates-stripe-transfers.md) | Redemption Fraud Detection gates Stripe transfers: one gate, recorded human decisions, denied credit to the employer for suspected abuse | Accepted, implemented |
| [0017](0017-bid-impact-from-the-ledger.md) | BID impact numbers come from the ledger and roll up the HR dashboards; an outside study's recirculation rate shown only as a labelled estimate | Accepted, implemented |
| [0018](0018-only-cloudfront-reaches-beanstalk.md) | Only CloudFront reaches Beanstalk (with a kill switch); unsafe production settings stop a deploy | Accepted, implemented |
| [0019](0019-personal-contacts-vote-separately.md) | Personal contacts vote in the blind adjudication, reported separately and never in the headline | Retired by 0041 |
| [0020](0020-adjudication-in-balanced-batches-of-10.md) | Blind adjudication in balanced batches of 10, with vote counts and "too few votes to call" | Retired by 0041 |
| [0021](0021-one-step-buy-credits-and-a-platform-fee-account.md) | One-step Buy credits with embedded Checkout, and a platform fee (off) on its own platform account | Accepted, implemented |
| [0022](0022-platform-set-up-stripe-accounts-for-demo-merchants.md) | Platform-set-up Stripe test accounts for the fictional demo merchants with no login (Express can't be prefilled), honestly labelled | Accepted, implemented |
| [0023](0023-product-menus-are-display-only.md) | Product menus for the demo merchants: the amount is the total, items are display only and never sent to the fraud AI | Accepted, implemented |
| [0024](0024-mission-framing-and-the-labelled-3x-line.md) | Lead with the buy-local mission; "roughly 3x" only next to its outside-study label and source (replaces 0017's no-multiplier rule) | Accepted, implemented |
| [0025](0025-transit-lines-brand.md) | Transit lines brand and Logo A, light and dark tokens, visible button states, disclosure menus | Accepted, implemented |
| [0026](0026-pay-in-person-with-pay-codes.md) | Pay in person: one-time 6-character pay codes the merchant confirms, through the same RedemptionService and TransferGate; channel display only; held payments can be cancelled | Accepted, implemented |
| [0027](0027-dc-sales-tax-shown-at-redemption.md) | DC sales tax shown at redemption: rates by date in config, added on menu items only, snapshotted on each redemption; the amount stays the total the AI, ledger and Stripe use | Accepted, implemented |
| [0028](0028-refunds-and-corrections.md) | Refunds and corrections: requests, a platform admin decides with a reason, every fix an append-only ledger line backed by a Stripe test-mode reversal, refund or the existing payout path, confirmed by the webhook; reconciliation matches | Accepted, implemented |
| [0029](0029-merchant-fee-ready-but-at-zero.md) | A merchant fee on each sale, ready but at 0: an audited platform-admin setting, snapshotted per redemption, held back from the Stripe transfer, given back in proportion on refunds, reconciled; judges see no amounts | Accepted, implemented |
| [0030](0030-business-model-projections.md) | A business model and impact projections: one config of sourced or labelled assumptions, a pure monthly calculator, three scenarios with low/base/high, customer funds and breakage never revenue; figures only on the signed-in Business model page and the README section, always "Projection, not results" | Accepted, implemented |
| [0031](0031-districts-partnerships-merchant-joining.md) | Districts, partnerships and merchant joining: DC's BID boundary stored and enforced (approval inside only, district credits only at approved live merchants, one active exclusive partnership per district in the database), a logged partnership record, and a public apply → check → BID approval → Stripe → live pipeline where the AI only suggests | Accepted, implemented |
| [0032](0032-live-demo-activity-in-stripe-test-mode.md) | Live demo activity in Stripe test mode: a scheduled generator makes a little real activity each weekday through the normal services (real fraud checks, Stripe test payments, transfers, refund requests), never backdated and never deciding anything; test mode only, daily and queue caps, a kill switch that is off by default, marked wherever it appears | Accepted, implemented (off until switched on) |
| [0033](0033-customer-funds-and-the-solvency-rule.md) | Customer funds and operating funds, and the solvency rule: every ledger line in one tranche; money in hand must cover every promise (each account above zero) at every moment, checked over the whole history, enforced after every money operation and before every Stripe transfer, shown on Where the money is; simulated refunds of paid-out sales are pulled back (supersedes part of 0028) | Accepted, implemented |
| [0034](0034-two-separate-stripe-balances.md) | Two separate Stripe balances: the platform balance holds customer funds only, a connected account Local Goods owns holds its operating money, and fees move between them only by a recorded sweep the solvency guard checks | Accepted, implemented |
| [0035](0035-grouped-admin-menu-and-admin-home.md) | A grouped, collapsible admin menu, a Home page for each admin, and page titles that match their menu labels | Accepted, implemented |
| [0036](0036-no-card-preview-yet.md) | No card preview yet: Stripe Issuing switches on instantly in test mode, but funding cards needs a business account behind an identity check, which we chose not to complete with invented details; a scratch trial stopped at funding and nothing was built | Accepted, not built |
| [0037](0037-custom-domain.md) | The site moves to uselocalgoods.com: APP_URL is the bare domain and a CloudFront Function sends www and the old cloudfront.net address there with a 301, keeping path, query and judge-link tokens; `/stripe/webhook` and `/up` are never redirected | Accepted, implemented (switch made in the consoles) |
| [0038](0038-redesign-allowed.md) | Redesign allowed: new fonts, palette, layout and components around the metro line and stop; the name, logo files, taglines, honesty rules and content stay; logo teal and coral are the anchors (supersedes the visual parts of 0025); direction A, Wayfinding: a transit-diagram district map, sections as stops on one line, Public Sans with Overpass Mono for ledgers | Accepted, not yet built |
| [0039](0039-history-rewrite.md) | Names removed from git history: one partial rewrite from `2d585fb` (old hash `6b68968`, before the 2026-11-07 rewrite; 321 of 440 commits) replaces the redacted names with "[name removed]"; HEAD's tree, the labels and the fraud lock commit unchanged; label lock re-locked at the new labeling commit; never again without Finn's say-so | Accepted, implemented |
| [0040](0040-demo-account-addresses.md) | The four demo logins move to fictional organisations' addresses with `demo:update-emails` (dry run by default, email column only, judges and platform admin excluded, rolls back if a reviewer link differs); the seeder skips a role until it has moved | Accepted, implemented |
| [0041](0041-blind-adjudication-retired.md) | Blind adjudication retired with no votes: a code setting closes voting, old links show a closed page, stored data kept and read-only for the platform admin | Accepted, implemented |
| [0042](0042-employer-platform-fee-switched-off.md) | Employer platform fee per participating employee (last month's credit recipients × the projection's base price), added once a month to the first credit purchase as its own Checkout and platform ledger line, only after Stripe confirms; never credits, never refundable; never on with the percent fee; built and tested, switched off during the pilot | Accepted, implemented (switched off) |
| [0043](0043-bid-program-fee-and-unspent-credit-estimate.md) | Projection only: the BID one-time start-up fee becomes an annual program fee by district size (Small $1,000, Medium $2,500, Large $5,000; pilot district free for 12 months); merchant fee reason stated; an unspent-credit estimate (about 8%) shown next to revenue, never counted; no charging code | Accepted, implemented (projection and wording only); free pilot year superseded by 0044 |
| [0044](0044-bid-program-fee-charged-no-pilot-year.md) | The BID annual program fee: no free pilot year (every district pays from its program start date), and charged in Stripe test mode behind `BID_PROGRAM_FEE_ENABLED` (off by default): price from the district's size tier, one payment per district per program year, recorded only from a verified webhook, Local Goods revenue kept apart from customer funds, never refunded in the app | Accepted, implemented (switched off) |
